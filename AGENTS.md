# Guide for AI agents working in this repository

Read this before changing anything. `docs/HISTORY.md` explains why the project is shaped
this way; `docs/ROADMAP.md` says what to work on.

## What this is

A desktop build of Audionook, a text-to-speech audiobook app. It runs entirely on the
user's machine: no server, no Docker, no account. The app is plain browser JavaScript
(ES modules, no framework, no bundler step for the app's own code) inside a Tauri shell.

## Layout

| Path | Contents | Edit? |
|---|---|---|
| `app/index.html` | Page skeleton | Yes |
| `app/src/*.js`, `styles.css` | The app. Most files are the original web app's modules with small patches. | Yes, with care (see below) |
| `app/src/desktop.css` | Styles added for this build | Yes |
| `app/vendor/`, `app/src/espeak-ng/`, `app/src/paradee13-rt.bundle`, `app/src/paradee-tokenizer.json` | Generated by `npm run vendor` | Never. Not committed. |
| `tools/build-vendor.mjs` | Assembles libraries, fonts and the Light voice bundle | Yes |
| `tools/serve.mjs` | Development server | Yes |
| `src-tauri/` | Desktop shell and installer settings | Yes |
| `reference/perchance-src/` | The original source, unmodified | Never. It is the comparison baseline. |
| `.github/workflows/build.yml` | Windows installer build | Yes |

## Commands

```bash
npm install
```

```bash
npm run vendor
```

```bash
npm run serve
```

`npm run vendor` downloads the Light voice model from Hugging Face (hosts:
`huggingface.co`, `us.aws.cdn.hf.co`). Behind a proxy that Node's `fetch` does not pick up,
run it as `NODE_USE_ENV_PROXY=1 npm run vendor`. `npm run build` builds the installer and
needs Rust plus, on Windows, the Microsoft C++ Build Tools; normally GitHub Actions does it.

## Rules

1. **Nothing loads from a CDN at run time.** Every third-party file goes through
   `tools/build-vendor.mjs` and is referenced from `app/src/vendor.js`. Workers are created
   from blob URLs, so those URLs must be absolute. The only run-time downloads allowed are
   the Kokoro model and voices from Hugging Face.

2. **Keep patches to original modules small and marked.** When changing a file that came
   from `reference/perchance-src/`, change as little as possible and start the comment with
   `Desktop build:` so the difference from the original is easy to find. Put new behaviour
   in new files where you can. The engine's WebGPU handling carries a warning from its
   author not to simplify it; respect that.

3. **Server-backed features stay off.** `app/src/platform.js` holds the switches
   (`explore`, `sharing`, `deviceSync`, `ai`) and the local `root` object that replaces the
   original host's plugins. Do not re-enable Explore, sharing or device sync: their servers
   belong to someone else. AI features are shown disabled; they come back only through
   `connectAi`.

4. **Do not change how text is split into clips without a migration.** Saved positions and
   bookmarks are clip numbers from `splitTextIntoChunks`. Changing the splitting shifts
   every saved place in existing libraries.

5. **Do not add a licence file or imply one.** The original app's code has no licence. See
   `CREDITS.md`.

6. **Keep the documents current.** A user-visible change gets a line in `CHANGELOG.md`.
   Finished or newly discovered work updates `docs/ROADMAP.md`.

## Testing

There is no committed test suite yet; adding one is the first item in the roadmap. Until
then, verify changes in a real browser, not by reading the code:

- Serve `app/` with the cross-origin isolation headers (`tools/serve.mjs` sends them).
  Opening `index.html` from disk does not work.
- Drive it with Playwright. `window.__app` exposes the app state: `__app.player`,
  `__app.engine`, `__app.engineStatus`, `__app.settings`, `__app.failedChunks`.
- Block every request that is not to the local server, and fail the test if one is
  attempted. This is how "works offline" is proved.
- For narration, check that the audio blobs decode and are not silent. That shows speech
  was produced; it does not show it sounds right. Only a person can judge that, so say so.
- Controls that are deliberately disabled carry `aria-disabled="true"`; Playwright will not
  click them without `force: true`.

The installer cannot be run in a Linux container. After pushing, read the GitHub Actions
result and logs before reporting that a build works, and state plainly what was verified in
a browser versus on Windows.

## Working with the owner

The owner directs; the agent implements. Lay out options with their trade-offs and a
recommendation, and let the owner decide matters of product direction. Report what was
tested and what was not. Do not describe something as working when it has only been
written.

Development happens on a feature branch, not `main`. Do not open a pull request unless
asked.
